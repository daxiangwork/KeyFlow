# KeyFlow Actions Ring 第一阶段：功能与 UI 设计需求

> 本文档保留为早期设计草案。当前实现支持自定义触发规则、操作位编辑与撤销/重做，实际行为以 `README.md` 和 `Docs/使用说明.md` 为准。

## 1. 功能定位

Actions Ring 是 KeyFlow 的快捷操作浮层。用户长按 JZ M5 中键，在当前光标附近打开一个环形菜单，再选择要执行的 Smart Action。

它与现有 Smart Actions 的关系是：

- **Smart Actions**：按下绑定按键，立即执行规则。
- **Actions Ring**：先显示一组可用规则，由用户选择本次要执行的规则。

本阶段重点验证：**不离开当前应用、不转移输入焦点，也能快速执行已有 Smart Action。**

## 2. 第一阶段范围

### 必须实现

- 全局、单层 Actions Ring。
- 最多显示 8 条 Smart Action。
- 长按 JZ M5 中键 600ms 打开。
- 在触发时的光标位置附近显示。
- 支持鼠标选择、外部点击取消、Esc 关闭。
- 复用现有 Smart Actions 规则与 ActionEngine。
- 打开浮层时不抢占原应用的输入焦点。
- 保留现有浅灰白视觉体系。

### 本阶段不实现

- 不提供 Actions Ring 操作位编辑器。
- 不做文件夹、子菜单或分页。
- 不做应用专属配置。
- 不做第三方插件、AI 助手、账号或云同步。
- 不做大中小尺寸切换。
- 不做音量等参数拖动调整。
- 不做 Tab、方向键等完整键盘导航，仅保留 Esc。
- 不改变现有首页、设置页和 Smart Actions 页面结构。
- 不新增产品 Logo 或重绘现有 Logo。

## 3. 规则来源与操作位

第一版不需要额外配置页面，直接读取现有规则：

- 仅使用**已启用**的 Smart Action。
- 按当前规则列表顺序取前 8 条。
- 已停用规则不显示。
- 超过 8 条时，仅显示前 8 条。
- 不足 8 条时，按实际数量排列，不显示空白占位操作位。
- 修改原规则后，Actions Ring 中的名称、图标和执行内容同步更新。
- 不复制规则 JSON，操作位通过规则 UUID 引用原规则。

无可用规则时：

- 不打开一个空 Ring。
- 显示轻量提示：“暂无可用的 Smart Action，请先创建并启用规则。”
- 不阻断其他操作，不使用全屏弹窗。

## 4. 交互流程

### 打开

```text
长按中键 600ms
→ 打开 Actions Ring
→ 松开中键不执行任何动作
```

打开时：

- 使用触发瞬间的光标位置，不持续跟随光标移动。
- 显示在当前光标所在的显示器。
- 面板不能成为前台应用，原 App 的焦点与输入状态必须保留。
- 不显示 Dock 图标变化，不激活 KeyFlow 主窗口。

### 选择并执行

```text
点击某个操作位
→ 关闭 Actions Ring
→ 执行对应 Smart Action
```

要求：

- 操作位包含图标与规则名称，不能只靠图标表达。
- Hover 时有清晰反馈，但不能引起 Ring 布局变化。
- 点击后只允许执行一次，不允许重复触发。
- 执行结果复用现有 Smart Actions 的结果反馈区域。
- 菜单栏不增加执行历史。

### 取消

支持两种方式：

- 点击 Ring 外部：关闭浮层，不执行动作。
- 按 Esc：关闭浮层，不执行动作。

外部点击的鼠标事件可以正常传给原应用，不需要阻断用户工作流。

## 5. 冲突与状态处理

### 与现有中键长按规则冲突

同一个“中键 · 长按”不能同时触发 Actions Ring 和 Smart Action。

- 如果已有启用的“中键 · 长按”规则，Actions Ring 不触发。
- 显示提示：“中键长按已被现有规则使用，请调整该规则后再使用 Actions Ring。”
- 不自动停用或覆盖用户规则。
- 设计师需要提供该冲突提示的样式。

### 全局 Smart Actions 已暂停

- 不响应中键长按。
- 如果 Ring 已打开，则立即关闭。

### 设备断连

- 如果 Ring 已打开，则立即关闭。
- 不执行尚未选择的动作。
- 已创建的规则与 Ring 配置不受影响。

### 浮层显示期间

- 暂停其他鼠标 Smart Action 触发，避免一次点击同时执行多条规则。
- 阻止连续打开多个 Ring；任意时刻只能存在一个浮层。

## 6. 视觉要求

沿用现有设计规范：

| 角色 | 色值 |
| --- | --- |
| 页面/浮层背景 | `#FAFAFA` / `#FFFFFF` |
| 主文字 | `#1A1A1A` |
| 辅助文字 | `#6B6B6B` |
| 边线 | `#E6E6E6` |
| Hover | `#F0F0F0` |
| 主操作/选中 | `#1A1A1A` |
| 成功 | `#1C9C85` |
| 警告 | `#A8611B` |
| 错误 | `#B84242` |

补充要求：

- 使用 macOS 系统字体和简体中文，技术名词保留英文。
- 浅色主题，不使用蓝色品牌按钮、渐变或品牌光效。
- Ring 采用轻量白色浮层、细边线、低透明度阴影。
- 操作位以圆形或近圆形为主，但不能因外观牺牲名称可读性。
- 长规则名称必须截断或换行，不得撑破浮层。
- Hover、Pressed、Disabled 和键盘焦点状态清晰。
- 浮层不遮挡中心操作位本身，不添加 Logo 或产品宣传文案。

## 7. 屏幕边缘适配

浮层默认以光标为中心展开，但必须完整落在当前显示器可见区域内：

- 与屏幕边缘至少保留 12px 间距。
- 光标靠近左右边缘时，浮层向可用方向偏移。
- 光标靠近顶部或底部时，调整垂直展开方向。
- 多显示器环境下，不跨屏显示，不使用另一块屏幕的坐标。
- 浮层移动后，操作位之间的相对结构不能改变。

## 8. 请输出的设计页面

1. **完整 Ring**：8 个操作位，展示默认、Hover 和选中状态。
2. **少量操作位**：2–3 条规则，验证排列方式。
3. **屏幕边缘状态**：顶部、底部、左侧、右侧的浮层偏移效果。
4. **无可用规则提示**。
5. **中键长按冲突提示**。
6. **执行成功与执行失败后的反馈位置**。
7. **设备断连或全局暂停导致 Ring 关闭的状态说明**。

不需要设计操作位编辑器，也不需要设计文件夹、插件市场或应用配置页面。

## 9. 验收场景

设计应能覆盖以下流程：

### 场景 A：选择并执行

```text
有 5 条启用规则 → 长按中键 → 打开 Ring
→ 点击第 2 条 → Ring 关闭 → 原 App 内执行对应动作
```

### 场景 B：取消

```text
打开 Ring → 改变主意 → 点击外部或按 Esc
→ Ring 关闭 → 不执行任何动作
```

### 场景 C：屏幕边缘

```text
在屏幕右下角打开 Ring
→ 浮层向左上偏移 → 所有操作位完整可见
```

### 场景 D：触发冲突

```text
中键长按已绑定其他规则
→ 不打开 Ring → 显示冲突原因 → 原规则配置不被修改
```

### 场景 E：设备或全局状态变化

```text
Ring 已打开 → 拔出接收器或暂停 Smart Actions
→ Ring 立即关闭 → 不执行动作
```

## 10. 最终体验目标

操作自然、打开迅速、不会误触发、不会打断当前工作，并且与现有 Smart Actions 使用同一套规则和执行逻辑。

设计应以实际交互状态为重点，不要只提供 Ring 的静态概念图。请输出高保真页面、操作位组件、状态说明和边缘适配示例。
